# Этап 8 (опционально) — VPS: релей и зашифрованная копия

Статус: **не начат: нужен ваш сервер.** Этап опциональный (решение этапа 0: сначала чистый P2P). Здесь только проект решения,
чтобы архитектура ничего не запрещала и работа началась, как только сервер появится. Кода этапа нет.

## Зачем

1. **Облачная копия на случай, когда обе машины выключены или сломаны** (критерий из плана: данные можно восстановить с сервера, сервер не видит содержимое).
2. **Связь, когда прямого пути нет** (разные сети, строгий NAT): релей. Сейчас это делает DERP Tailscale; свой релей нужен, только если он не устраивает.

## Как делать (предварительное решение)

| Что | Решение | Причина |
|---|---|---|
| Зашифрованная копия | Syncthing на VPS как **ненадёжное устройство** (`untrusted`): папки для него шифруются паролем на стороне клиента (имена и содержимое файлов), сервер хранит только шифртекст | готовая функция Syncthing, своей криптографии нет; принцип «сервер не видит содержимое» выполняется по построению |
| Доступ к серверу | VPS входит в ту же tailnet Tailscale, публичные порты не открываются | та же модель безопасности, что у двух машин; нечего атаковать снаружи |
| Релей | не нужен, пока устраивает DERP; при необходимости `strelaysrv` на том же сервере | не усложнять заранее |
| Пароль шифрования папок | не синхронизируется и не хранится в манифесте: вводится на каждой машине один раз и кладётся в Credential Manager (DPAPI) | секреты не должны ехать по сети в открытом виде; потеря пароля = потеря облачной копии, поэтому его нужно хранить отдельно (менеджер паролей) |
| Восстановление | `envsync restore --from-vps` на чистой машине: подключает серверное устройство, запрашивает пароль, подтягивает папки | сценарий «обе машины сломаны» |
| Манифест | раздел `vps:` (схема 3): имя в tailnet, Device ID сервера, какие папки зеркалировать | остаётся декларативным |

## Что нужно от владельца

1. VPS (ОС, объём диска больше суммарного размера синкаемых данных плюс запас на версии).
2. Решение: ставить ли VPS в tailnet (рекомендуется) и кто будет обновлять сервер.
3. Какие папки зеркалировать (реальные данные синхронизируются только после включения `allowLiveData`, см. этап 6).

## Критерий готовности (из плана)

При выключенных обеих машинах данные можно восстановить с сервера, а сервер не видит содержимое.
Проверка: тест на трёх экземплярах Syncthing (две машины и «сервер» с `untrusted`): после выключения двух восстановление на третьем
с паролем даёт те же файлы; без пароля содержимое и имена нечитаемы.

## Риски

- Потерян пароль шифрования: копия бесполезна. Нужна явная процедура хранения пароля.
- Версионирование на «ненадёжном» устройстве работает по правилам Syncthing для зашифрованных папок; объём диска сервера нужно считать с запасом.
- Сервер — ещё одна точка, которую надо обновлять; в манифесте и интерфейсе его состояние должно быть видно наравне с машинами.
