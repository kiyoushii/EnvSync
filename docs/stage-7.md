# Этап 7 — интерфейс

Статус: **выполнен** (11.11.2026). Ветка `stage-7-ui` (от `stage-6-safety`).

## Цель и критерий

Состояние обеих машин, решения, конфликты, журнал и экран «что не синхронизируется» видны без командной строки.
Критерий из плана: **я могу увидеть состояние обеих машин без командной строки.**

## Что сделано

| Что | Где |
|---|---|
| Локальный веб-интерфейс на `127.0.0.1` (статус обеих машин, решения предохранителя, конфликты, настройки от другой машины, журнал, «не синхронизируется») | `internal/ui` |
| Данные интерфейса из настоящих источников: Tailscale, Syncthing, папка состояний, журнал | `internal/app` |
| Статус каждой машины раз в 15 с записывается в папку состояний и едет через Syncthing: вторая машина видит эту без командной строки | `app.Backend.ExportStatus` |
| Иконка в трее: цвет по общему состоянию, меню (открыть, пауза, выход) | `cmd/envsync/tray_windows.go` |
| `envsync run` запускает всё сразу: Syncthing, предохранитель, интерфейс, экспорт статуса, трей (`--no-tray`, `--no-ui`) | `cmd/envsync/run.go` |
| `envsync ui` открывает интерфейс запущенного агента; `envsync checklist` печатает чек-лист ручной настройки | `cmd/envsync` |

## Экраны

- **Состояние**: карточка этой машины (вживую) и карточка другой (по снимку из папки состояний, с возрастом снимка; устаревший больше 3 минут подсвечивается):
  Tailscale, Syncthing, связь с устройствами, папки с числом файлов, тем, что ждёт получения, и ошибками.
- **Решения**: папки, остановленные предохранителем, с кнопками «Отклонить: вернуть файлы» и «Принять удаление» (с подтверждением).
- **Конфликты**: конфликтные копии со всех папок (обе версии сохранены), с оригинальным именем, временем и размером.
- **Настройки**: что изменилось бы на этой машине по настройкам другой (dry-run, только просмотр; применение командой с подтверждением и снимком).
- **Журнал**: журнал аудита, новые сверху.
- **Не синхронизируется**: постоянное по природе (драйверы, Wi-Fi, лицензия…), исключения папок, действующие сейчас, конфиги,
  не взятые как секреты, программы вручную. Тот же список строит `envsync checklist` (чек-лист ручной настройки новой машины).
- Кнопка «Пауза всего» / «Возобновить» всегда вверху.

## Безопасность интерфейса

Интерфейс управляет синхронизацией, поэтому его нельзя оставлять доступным постороннему сайту или процессу:

- слушает **только `127.0.0.1`**;
- доступ по **случайному токену** (создаётся при каждом запуске агента, лежит в файле только для пользователя); из адреса токен сразу
  уходит в куку `HttpOnly; SameSite=Strict`, адрес очищается;
- проверка **`Host`**: чужое имя отклоняется даже с верным токеном (защита от DNS rebinding);
- изменяющие запросы только `POST`, с обязательным служебным заголовком и совпадающим `Origin` (защита от CSRF с чужого сайта);
- `Content-Security-Policy: default-src 'none'`, скрипты и стили только свои, без `unsafe-inline`; `X-Frame-Options: DENY`;
- страница выводит данные только через `textContent` (имена файлов приходят извне): тест запрещает `innerHTML` и подобное.

## Проверки

- Юнит-тесты интерфейса: токен (заголовок, кука, перенос из адреса), чужой `Host`, `GET` вместо `POST`, нет служебного заголовка, чужой `Origin`,
  решения и пауза доходят до бэкенда, ошибка бэкенда как JSON, порядок журнала, пустые списки как `[]`, статика и защитные заголовки,
  запрет `innerHTML`.
- Бэкенд на настоящих данных: статус без Syncthing, недоступный Tailscale, **статус одной машины доезжает до другой через папку состояний**,
  экран «не синхронизируется» (постоянная и динамическая части, секреты из состояния), разбор имён конфликтных копий.
- Внешний вид проверен в браузере на демо-данных двух машин (все вкладки, узкое окно, тёмная тема).

## Что осталось

- Иконку в трее и её меню я проверить не мог (нужен просмотр панели задач вживую): логика цвета и меню в коде, значок строится программно (круг в ICO).
  Проверка на ваших машинах входит в итоговый пакет проверок.
- Применение настроек и программ из интерфейса кнопками не сделано намеренно: эти действия меняют систему и остаются командами
  с подтверждением (`envsync settings apply`, `envsync software apply`). Интерфейс показывает, что изменится.
- Автозапуск агента при входе в систему: этап 9.
