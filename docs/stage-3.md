# Этап 3 — манифест и профили машин

Статус: **выполнен** (11.11.2026). Ветка `stage-3-manifest` (от `stage-2-files`).

## Цель и критерий

Один манифест `envsync.yaml` описывает, что синкается, и корректно работает на обеих машинах, даже если
диски и пути у них разные. Критерий из плана: **один манифест корректно работает на обеих машинах с разными буквами дисков.**

## Что сделано

- `internal/core`: схема манифеста, разбор со строгой проверкой, переменные путей, профили машин, проверка путей.
- `internal/transport/folder.go`: `ApplyFolder` — общий способ создать папку в Syncthing и открыть её для всех устройств
  (им же теперь пользуется `pair`).
- Команды: `envsync manifest check` (ничего не меняет, умеет «примерять» манифест на другую машину), `envsync apply` (dry-run и подтверждение).
- [envsync.example.yaml](../envsync.example.yaml) — пример без личных данных; тест следит, чтобы он оставался корректным.

## Схема манифеста (версия 1)

| Раздел | Смысл |
|---|---|
| `schema` | версия схемы; агент старее манифеста отказывается его применять |
| `vars` | свои переменные путей, доступны как `{{имя}}`, могут ссылаться друг на друга |
| `ignore` | общие исключения; если раздела нет, берутся `core.DefaultIgnores` |
| `folders[]` | `id` (одинаков на всех машинах), `path`, `ignore` (добавляется к общим), `keep_days`, `test` |
| `machines.<ИМЯ>` | профиль машины: `vars` (например другой `sync_root`) и `folders.<id>` с `path` или `skip: true` |

Встроенные переменные: `{{user}}`, `{{home}}`, `{{appdata}}`, `{{localappdata}}`, `{{machine}}`.
`{{sync_root}}` по умолчанию равен `{{home}}`, на машине с другим диском его переопределяют в профиле.
Имя машины сравнивается без учёта регистра. Имена переменных регистронезависимы.

## Решения и причины

| Решение | Причина |
|---|---|
| Разбор строгий: неизвестное поле или опечатка — ошибка | «настройка молча не применилась» хуже, чем отказ |
| Манифест новее агента не применяется | агенты разных версий не должны портить друг другу данные |
| `Env` (имя, пользователь, профиль) передаётся в `Resolve`, не читается внутри | можно проверить «как на другой машине»: `manifest check --machine X --home D:\...` |
| Пути проверяются после подстановки: абсолютные, не корень диска, не `Windows`/`Program Files`/`ProgramData`, не вложены друг в друга | защита от манифеста, который синканул бы лишнее |
| Список `ignore` в манифесте заменяет список по умолчанию целиком; без него действует список по умолчанию | по умолчанию безопасно (`.git`, кэши), при желании всё явно перечисляется в манифесте |
| `ApplyFolder` отказывается перенацелить существующую папку на другой путь | Syncthing увидел бы пустое место и мог бы разослать «удаление» всех файлов второй машине |
| `apply` синкает только папки с `test: true`, пока `allowLiveData` в `settings.json` не включён | до этапа 6 (откат, предохранитель массового удаления) реальные данные не трогаем |
| Папка, пропущенная на машине (`skip`), не принимается автоматически | у устройств `autoAcceptFolders: false`; запрос остаётся «ожидающим» |

## Как манифест попадает на обе машины

Источник истины — приватный git-репозиторий (решение этапа 0). Агент читает локальный файл:
`manifestPath` из `settings.json` или `envsync.yaml` в папке агента (`%LOCALAPPDATA%\EnvSync`). Репозиторий манифеста
создаёт владелец (он содержит личные пути); в этом репозитории лежит только пример. Автоматическая выкачка
манифеста из git — часть этапа 9 (установщик).

## Проверки

- Юнит-тесты ядра: разбор и отказы на плохих манифестах, цепочки переменных, профили (в том числе регистр имени и неизвестная машина),
  исключения и `keep_days`, опасные и пересекающиеся пути, **один манифест на двух машинах с разными дисками (`D:\Sync` и `F:\…`)**.
- Юнит-тесты `ApplyFolder`: идемпотентность, несколько устройств, отказ перенаправлять существующую папку.
- Интеграционный тест на двух настоящих Syncthing: один манифест, синк-корень на «разных дисках»,
  папка с одним ID связывает машины, файлы с кириллицей ходят в обе стороны, пропущенная на одной машине папка туда не попадает.

## Что осталось на следующие этапы

- Ключи реестра, программы, адаптеры приложений: разделы манифеста добавятся с повышением `schema` (этапы 4 и 5).
- Реальные папки в манифесте: после этапа 6.
- Junction-ссылки для одинаковых путей при разных дисках: не нужны, пока совпадают буквы дисков (на обеих машинах только `C:`).
