# Этап 1 — сеть и сопряжение

Статус: **черновик плана, ждёт «ок» на установку**. Ветка `stage-1-network`.

## Цель

Две машины видят друг друга по защищённому каналу, и больше никто. Это фундамент:
всё остальное (файлы, настройки, программы) поедет поверх него.

Этап в `ARCHITECTURE.md` сокращён: транспорт — готовые Tailscale и Syncthing, своего
протокола и своей криптографии нет. Поэтому «агенты обмениваются тестовыми сообщениями»
из исходного критерия превращается в «тестовый файл доезжает с машины на машину через
Syncthing, а Syncthing слушает только Tailscale».

## Критерий готовности

1. ПК и ноутбук в одной tailnet, `tailscale ping` проходит в обе стороны.
2. Syncthing на каждой машине запущен агентом (не вручную), его REST и GUI доступны только на `127.0.0.1`, а порт синхронизации слушает только IP Tailscale.
3. Машины сопряжены командой `envsync pair`. Файл, созданный в тестовой папке на одной машине, появляется на второй.
4. Негативные проверки (раздел «Проверки») пройдены: посторонний Device ID и посторонний сетевой интерфейс подключиться не могут.
5. Всё работает только на тестовой папке. Профиль, реестр, настоящие данные не затронуты.

## Что ставим (требует твоего «ок», это изменение живой системы)

| Пакет | winget id | Версия на сегодня | Где нужен |
|---|---|---|---|
| Tailscale | `Tailscale.Tailscale` | 1.104.5 | обе машины |
| Syncthing | `Syncthing.Syncthing` | 2.1.7 | обе машины |
| Go | `GoLang.Go` | 1.27.4 | только там, где разрабатываем (ПК) |

Команды (dry-run — ничего пока не запущено):

```powershell
winget install --id Tailscale.Tailscale --exact
winget install --id Syncthing.Syncthing --exact
winget install --id GoLang.Go --exact
```

Что нужно знать:
- Установка Tailscale просит UAC (ставит сетевой драйвер). Это единственное место, где нужен администратор.
- **Вход в Tailscale делаешь ты сам** в браузере (аккаунт, пароли и SSO я не ввожу). На второй машине входишь в тот же аккаунт.
- Я не запускаю `winget` с автосогласием на лицензии за тебя: соглашения принимаешь ты.

## Шаги

### 1.1 Tailscale
- Войти на обеих машинах в один аккаунт, дать машинам понятные имена.
- Отключить истечение ключа для обеих машин (иначе через ~180 дней машина выпадет из сети).
- Проверка: `tailscale status`, `tailscale ping <другая машина>`.

### 1.2 Syncthing под управлением агента
Конфиг и данные Syncthing живут в своей папке агента (`%LOCALAPPDATA%\EnvSync\syncthing`), не в стандартной, чтобы не конфликтовать с возможной ручной установкой.

Настройки, которые агент задаёт при первом запуске:
- адрес синхронизации: `tcp://<tailscale-ip>:22000`, больше никаких;
- GUI/REST: `127.0.0.1` на отдельном порту, API-ключ генерируется агентом и хранится в его конфиге;
- выключены: глобальное и локальное обнаружение, релеи, NAT-проброс, анонимная статистика, автообновление Syncthing (обновляем через `winget`);
- папка `Default Folder` удалена;
- неизвестные устройства игнорируются, автопринятие папок выключено.

Если интерфейс Tailscale ещё не поднят (после включения машины), агент ждёт и повторяет, а не откатывается на «слушать везде».

### 1.3 Минимальный агент на Go
Только то, что нужно этапу, без модулей и манифеста:

```
cmd/envsync/            main, разбор команд
internal/transport/     запуск Syncthing, REST-клиент, настройка, Tailscale-статус
```

Команды:
- `envsync status` — Tailscale поднят? Syncthing запущен? Второе устройство подключено?
- `envsync id` — показать свой Device ID и Tailscale-имя.
- `envsync pair <device-id>` — добавить второе устройство (только если оно есть в `tailscale status`), показать dry-run, дождаться подтверждения.
- `envsync run` — запустить и держать Syncthing как дочерний процесс.

Пути, имена машин и тестовой папки берутся из флагов и конфига агента, в код не зашиваются.

### 1.4 Тестовая папка
Отдельная папка (по умолчанию `%USERPROFILE%\EnvSyncTest`), общая между машинами, с версионированием. Больше ничего на этапе не синкается.

## Проверки

Позитивные:
- файл, созданный на ПК, появляется на ноутбуке, и наоборот;
- перезапуск агента и перезагрузка машины: связь восстанавливается сама.

Негативные (обязательные для критерия):
- **Чужой Device ID.** Третий экземпляр Syncthing с другим ID пытается подключиться: отклонён, в конфиг не добавлен, автопринятия нет.
- **Чужой интерфейс.** `Test-NetConnection` на порт 22000 по LAN-адресу машины и по `127.0.0.1` не соединяется; открыт только Tailscale-адрес. Проверяем и `netstat -ano`.
- **Выход из tailnet.** Если выключить Tailscale на одной машине, синк останавливается и не уходит на другие пути.

Юнит-тесты агента: сборка конфига Syncthing (что именно выключено и на какой адрес привязано), разбор `tailscale status --json`, отказ `pair` для устройства вне tailnet.

## Риски

| Риск | Что делаем |
|---|---|
| Syncthing 2.x отличается от 1.x (другая БД и часть настроек) | Сверяемся с документацией 2.x и версией на деле, не по памяти |
| IP Tailscale может смениться | Адрес берём из `tailscale ip` при каждом запуске, не хардкодим |
| Сон/выход из сна, интерфейс поднимается позже агента | Ожидание с повтором, привязка только после появления интерфейса |
| Брандмауэр Windows спросит про Syncthing | Разрешить только для частной сети/Tailscale, ты подтверждаешь вручную |
| Ключ Tailscale истекает | Отключить expiry для обеих машин (шаг 1.1) |

## Что на твоей стороне

1. Дать «ок» на установку (три команды выше) на ПК.
2. Войти в Tailscale в браузере (ПК, потом ноутбук).
3. Повторить установку Tailscale и Syncthing на ноутбуке (Go там не нужен).
