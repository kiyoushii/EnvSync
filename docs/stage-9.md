# Этап 9 — установщик и новая машина

Статус: **выполнен в части кода и тестов** (11.11.2026). Полный сценарий «чистая Windows → та же среда одной командой» проверить
здесь нельзя (нет чистой машины и виртуальной машины), поэтому он проверен по частям, остальное в «Что осталось».
Ветка `stage-9-installer` (от `stage-7-ui`).

## Цель и критерий

Автозапуск, обновления и сценарий «поднять среду на чистой Windows за один запуск». Критерий из плана:
**чистая установка Windows после одной команды получает ту же среду.**

## Что сделано

| Что | Где |
|---|---|
| Автозапуск агента при входе пользователя: **задача планировщика**, обычные права, без администратора, перезапуск при сбое (решение этапа 0: не служба, потому что HKCU, обои и тема живут в сессии пользователя) | `internal/install`, `envsync install` / `uninstall` |
| Фоновый режим `envsync run --background`: без окна консоли, лог в `agent.log` (ротация 5 МБ) | `cmd/envsync/run.go`, `install.go` |
| Обновление зависимостей: `envsync update` (Syncthing и Tailscale через winget, после подтверждения) | `cmd/envsync/install.go` |
| `envsync version` (агент, Syncthing, Tailscale, автозапуск) и `envsync wait` (ждать готовности агента, код возврата для скриптов) | там же |
| **Сценарий новой машины одной командой** | `scripts/bootstrap.ps1` |
| Чек-лист ручной настройки (то, что не переносится) на рабочий стол | `envsync checklist` |

## Сценарий `scripts/bootstrap.ps1`

Одна команда в обычном PowerShell (UAC спросит только там, где его требует установщик):

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\bootstrap.ps1 `
    -ManifestFile C:\path\to\envsync.yaml `
    -PeerName DESKTOP-LS890QQ -PeerId <Device ID той машины>
```

Шаги (каждый подтверждается, если нет `-Yes`; `-DryRun` печатает все шаги и ничего не меняет):

1. проверить `winget`;
2. поставить Git, Go, Tailscale, Syncthing (принятие лицензий входит в ваше подтверждение шага);
3. собрать агента из репозитория (ветка `main`) в `%LOCALAPPDATA%\EnvSync\bin`;
4. **войти в Tailscale** (откроется браузер; вход делаете вы, тем же аккаунтом, что на первой машине);
5. положить манифест (файлом или из приватного git-репозитория манифеста);
6. `envsync init` и показать Device ID для сопряжения с другой стороны;
7. запустить агента в фоне и дождаться готовности (`envsync wait`);
8. `envsync pair` и `envsync apply` (папки по манифесту);
9. `envsync software plan` → установка недостающих программ после подтверждения;
10. дождаться состояния эталонной машины и `envsync settings plan --from <эталон>` → применение её настроек после подтверждения (со снимком для отката);
11. автозапуск и чек-лист ручной настройки.

Скрипт сознательно ASCII-only (как `measure.ps1`), чтобы не зависеть от кодировки в Windows PowerShell 5.1. Ничего не удаляет.

## Решения и причины

| Решение | Причина |
|---|---|
| Агент собирается на новой машине из репозитория, а не качается готовый `.exe` | релизов пока нет, и запускать скачанное без проверки не стоит; сборка из вашего репозитория проверяема. Когда появятся подписанные релизы, шаг 3 заменяется скачиванием с проверкой хеша |
| Автозапуск без администратора | принцип минимальных прав: агент работает от пользователя, админ-хелпер (HKLM, установка для всех пользователей) по плану добавляется последним и по умолчанию выключен |
| `envsync update` обновляет только Syncthing и Tailscale | агент обновляется тем же `bootstrap.ps1` (сборка актуальной ветки): без автоматического скачивания кода |
| Общий читатель stdin | ответы можно подавать через pipe, иначе второй вопрос получал бы пустой ввод |
| **Первый снимок настроек — «база», а не правка** (найдено при подготовке развёртывания) | иначе машина, запустившая агент позже, выглядела бы «новее» и навязала бы свои настройки эталону (ПК). Первичное выравнивание делается явно: `envsync settings apply --from <эталон>`; дальше работает «побеждает последняя правка» |
| Агент сам снимает настройки каждые 5 минут и список программ раз в час | вторая машина видит актуальное состояние без ручного `export`; это только чтение системы, применение по-прежнему с подтверждением |

## Проверки

- XML задачи: корректен, спецсимволы и кириллица в путях и имени пользователя экранируются, права `LeastPrivilege`, без SYSTEM, кодировка UTF-16 LE с BOM.
- **Настоящий планировщик Windows** принял XML: создание, замена, запрос и удаление безвредной тестовой задачи с уникальным именем; после теста не осталось ничего.
- `envsync wait` возвращает ненулевой код, пока агент не отвечает; `envsync version` показывает версии и состояние автозапуска.
- `bootstrap.ps1`: синтаксис проверен парсером PowerShell, файл ASCII-only, `-DryRun` печатает все шаги.
- Бэкенд интерфейса против настоящего Syncthing (интеграционный): реальный статус, папки, поиск конфликтных копий, пауза и возобновление, запись статуса.

## Что осталось (нужно вам)

- **Прогон `bootstrap.ps1` на настоящей чистой Windows** (или в Windows Sandbox/виртуальной машине): здесь нет ни той, ни другой. Скрипт рассчитан
  на это, но целиком не выполнялся; первую такую проверку лучше делать на запасной машине или виртуалке с `-DryRun`, затем без него.
- **Включить автозапуск** на ваших двух машинах (`envsync install`): я сознательно не включал его на вашем ПК. Перезагрузку с автоподъёмом (отложенную с этапа 1)
  вы проверите после включения.
- Первый вход в Tailscale на новой машине и ответ брандмауэра Windows (только частные сети) делаются вручную.
- Слияние веток этапов в основную ветку и смена ветки по умолчанию на GitHub: решение владельца репозитория.
