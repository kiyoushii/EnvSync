# Этап 5 — программы

Статус: **выполнен в части кода и тестов** (11.11.2026). Реальная установка пакета на ноутбуке требует вашего подтверждения
и запускается вами (см. «Что осталось»). Ветка `stage-5-software` (от `stage-4-settings`).

## Цель и критерий

Желаемый набор программ описан в манифесте и ставится через `winget`. Критерий из плана: **программа, добавленная в манифест,
устанавливается на второй машине после моего «ок»**.

## Как это работает

- Манифест (схема 2) получил раздел `software`: `winget` (пакеты с необязательной версией и областью `user`/`machine`),
  `remove` (явный список на удаление), `manual` (программы вне winget, показываются списком «поставить вручную»),
  а в профиле машины `software.skip` (на этой машине не ставить и не удалять). Манифест схемы 1 остаётся корректным.
- `envsync software scan` записывает список установленных пакетов этой машины в папку состояний (она синкается).
- `envsync software plan` (ничего не меняет): что поставить по манифесту; что стоит на машинах, но отсутствует в манифесте
  (готовые строки `- id: ...` для вставки, с пометкой, на какой машине стоит); несовпадение закреплённой версии; список «вручную».
- `envsync software apply` ставит недостающее после подтверждения. Перед этим показывает, что установка принимает
  лицензионные соглашения пакетов и что установщик может запросить UAC.
- `envsync software rollback` отменяет запуск: удаляет поставленное им (с подтверждением) и возвращает удалённое.

## Защита

- **Агент ничего не удаляет сам.** Удаление возможно только для пакетов из `software.remove`, только с флагом `--uninstall`
  и только после отдельного подтверждения каждого пакета. Пакет, которого нет в `remove`, не трогается никогда, даже если он пропал с другой машины.
- Откат не удаляет то, что стояло до запуска: только поставленное именно этим запуском; удаление при откате тоже подтверждается.
- Сбой установки одного пакета не останавливает остальные; ошибка попадает в журнал аудита.
- Закреплённая версия, не совпавшая с установленной, только сообщается (без тихих замен).
- Системные компоненты (VCRedist, .NET Runtime, WebView2 и т. п.) не предлагаются как «программы».
- Админ-хелпер для установки не нужен: `winget` сам запрашивает UAC там, где это требуется. Отдельный повышенный процесс
  остаётся на этап 9 (по плану добавляется последним и по умолчанию выключен).

## Проверки

- Критерий: «манифест с тремя программами, на втором компьютере не хватает двух; план показывает их, dry-run ничего не ставит,
  после apply они стоят, повторный план пуст».
- Предложения: программа, установленная на одной машине, предлагается второй к добавлению в манифест.
- Удаление: без флага, без подтверждения, с подтверждением; пакет вне `remove` не трогается.
- Сбой одной установки; закреплённая версия; разбор `winget export`; повторный `scan` не двигает `ChangedAt`.
- Цикл «применил → проверил → откатил» с подтверждением откатного удаления и возвратом удалённого.
- Манифест: раздел software требует схему 2, отклоняются плохие id, повторы, плохие `scope`, версии с опасными символами,
  пакет одновременно в `winget` и `remove`; профили `skip`.
- Только чтение, на реальной машине: `winget export` разобран (85 пакетов в источнике winget), `software plan` по примеру манифеста
  корректно находит установленные пакеты и предлагает остальные.

## Что осталось

- **Реальная установка и удаление пакета** (на ПК и ноутбуке) требуют вашего подтверждения: меняют систему и принимают лицензии.
  Команда: `envsync software apply` в вашем обычном терминале; тестовым пакетом можно взять небольшой (например `Notepad++.Notepad++`).
- Обновление уже установленных пакетов не входит в этап: агент ставит недостающее и сообщает о несовпадении версии.
- Источники кроме `winget` (например, Microsoft Store) пока не используются.
